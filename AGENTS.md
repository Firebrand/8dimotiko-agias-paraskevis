# 8ο Δημοτικό Σχολείο Αγίας Παρασκευής

Website for the 8th Primary School of Agia Paraskevi, replacing the legacy
WordPress site at `https://www.8dimotikoagp.gr`. Content is edited in Sanity;
the site is deployed on Vercel.

**All user-facing copy is Greek.** Keep it that way — including Studio field
labels, validation messages and empty states.

## Stack

- Next.js 16 (App Router, Turbopack) + React 19
- Tailwind CSS v4 (CSS-first config in `src/app/globals.css`, no JS config file)
- Sanity v6 with the Studio embedded at `/studio`
- Sanity Live Content API — published edits appear on the site without a redeploy

## Commands

| Command | Purpose |
| --- | --- |
| `npm run dev` | Dev server (falls back to :3001 if :3000 is taken) |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint (`next lint` no longer exists in Next 16) |
| `npm run wp:export` | Re-download the legacy WordPress content into `wp-export/` |
| `npm run migrate` | Import `wp-export/` into Sanity (idempotent) |
| `npm run migrate:dry` | Convert without writing; dumps `wp-export/_dry-run.json` |

Before considering work done: `npm run typecheck && npm run lint && npm run build`.

`node tools/crawl.mjs` requests every route on a running server and reports
failures. Run it against `npm run start` (`BASE_URL=http://localhost:3002`), not
`next dev` — the dev server throws spurious `JSON.parse` errors under
concurrent load on dynamic routes.

## Layout of the code

```
src/app/layout.tsx          Root shell: <html>, fonts, site-wide metadata
src/app/(site)/             Public pages — this group owns the header/footer
src/app/studio/             Embedded Sanity Studio, deliberately outside (site)
src/sanity/                 Client, Live wiring, image builder, schemas, GROQ
src/components/             UI; `rich-text.tsx` renders every Portable Text type
src/lib/legacy-redirects.ts GENERATED by `npm run migrate` — do not hand-edit
tools/                      One-off migration + verification scripts (plain .mjs)
wp-export/                  Legacy WordPress JSON + the resumable asset cache
```

### Things worth knowing

- **The Studio must stay behind a client boundary.** `sanity.config.ts` is
  imported from `src/app/studio/[[...tool]]/studio.tsx`, which is `"use client"`.
  Importing it from a Server Component pulls `sanity` into the RSC graph, where
  its `swr` dependency has no `react-server` default export and the build fails.
- **The Studio lives outside `(site)`** so it does not inherit the site header
  and footer. Public pages must stay inside `(site)`.
- **Legacy redirects are expanded in `next.config.ts`.** Next matches the *raw*
  pathname, so each entry is registered decoded and in both percent-encoding
  cases; the old WordPress URLs used lowercase hex.
- **Fonts must carry a Greek subset.** `Inter` and `Manrope` both do; most
  popular display faces (Figtree, Outfit, Plus Jakarta Sans, DM Sans…) do not.
  Check `node_modules/next/dist/compiled/@next/font/dist/google/font-data.json`
  before swapping one in.
- **`whitespace-pre-line` is load-bearing.** WordPress used `<br>` for line
  breaks; the migration preserves them as `\n` inside Portable Text spans, so
  paragraphs, list items and blockquotes all need that class.
- **Accent colour classes are written out in full** in `src/lib/utils.ts`.
  Tailwind v4 extracts class names statically, so they cannot be built by
  string concatenation.
- Section landing pages (e.g. `/to-scholeio-mas`) list their children from the
  `navigation` document rather than a parent/child field, so editors control
  both the menu and the landing page from one place.

## Content model

Documents: `post`, `page`, `category`, `staffMember`.
Singletons: `siteSettings`, `navigation`, `announcement` — reachable only from
the Studio sidebar; `sanity.config.ts` filters their create/delete actions.

Portable Text supports `figure`, `gallery`, `fileAttachment`, `dataTable`,
`videoEmbed`, `audioEmbed` and `callout`. Adding a type means touching three
places: the schema in `src/sanity/schemaTypes/`, the `BODY` projection in
`src/sanity/queries.ts`, and the renderer in `src/components/rich-text.tsx`.

## Migration notes

`npm run migrate` is safe to re-run: every document uses a deterministic `_id`
with `createOrReplace`, and uploaded assets are cached in
`wp-export/_asset-cache.json` (failed URLs are cached as `null` so dead links
are not retried).

Five source assets could not be migrated and are listed in
`wp-export/_asset-failures.json`: two images that already 404 on the legacy
site, and two `blob:` URLs left behind by the WordPress editor. These are
defects in the original site, not the migration.

The sitemap, staff directory and school contact details are curated by hand in
`tools/lib/site-content.mjs` rather than scraped, because the WordPress
originals were unstructured prose and included placeholder pages.
